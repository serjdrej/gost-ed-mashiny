# gost-ed-mashiny

Если вы выпускаете машину или оборудование для рынка РФ/ЕАЭС, к ней обязателен
комплект эксплуатационной документации нормированной структуры — руководство по
эксплуатации и паспорт — как часть пакета для декларирования или сертификации.
Без строгой структуры ИИ-ассистент обычно пишет вольный, маркетинговый текст или
молча подставляет правдоподобные цифры там, где должны быть данные из протокола
испытаний. Этот Agent Skill для Claude Code ведёт через официальную структуру и
не даёт спрятать пробел за красивой фразой.

Результат — **черновик**, для проверки ответственным инженером или
специалистом по подтверждению соответствия перед подачей в орган по
сертификации/декларированию, а не готовый к подаче документ.

## Что делает

- Собирает **руководство по эксплуатации (РЭ)** по ГОСТ Р 2.610-2019 —
  `references/re-structure.md`.
- Собирает **паспорт (ПС)** по ГОСТ Р 2.601-2019, включая формуляр и КДС как
  альтернативы — `references/ps-structure.md`.
- Проверяет собранный комплект на структурную полноту по ТР ТС 010/2011 —
  `references/trts-010-checklist.md`.
- Проверяет статус применяемых ГОСТ и маршрут к действующему тексту ТР ТС
  через `scripts/gost_lookup.py` — вживую, по открытым данным Росстандарта
  (`references/norms-registry.md`).

Триггеры: эксплуатационная документация, руководство или инструкция по
эксплуатации, паспорт изделия, формуляр, ЗИП, КДС — для машины, станка,
строительного или технологического оборудования; подготовка комплекта для
декларирования или сертификации по ТР ТС 010/2011 (EAC).

## Чего НЕ делает

- **Не инженерная проверка, а структурная.** Аудит по
  `trts-010-checklist.md` проверяет, что нужные сведения физически
  присутствуют в тексте — не пересчитывает и не подтверждает сами значения
  (уровень шума, ресурс и т.п.).
- **Не выдумывает нормируемые значения.** Числа — только из протоколов
  испытаний или расчётов изготовителя; при их отсутствии — видимый плейсхолдер,
  не правдоподобная цифра.
- **Не переводит и не копирует документацию конкурента** — только собственный
  текст по своей машине.
- **Не отвечает по памяти на стандарт или регламент вне реестра.** Другой
  ГОСТ, другой регламент ТР ТС, маркировка CE или требования другой страны,
  практика органа по сертификации — вне периметра. `SKILL.md`, раздел
  «Протокол пробела в базе»: скилл либо ищет живьём через `gost_lookup.py` и
  помечает находку **AD HOC**, либо прямо говорит, что вопрос вне базы, и
  спрашивает, как продолжать.

## Как установить

**Claude Code, через маркетплейс** (проще всего):
```
/plugin marketplace add serjdrej/ru-legal-skills
/plugin install gost-ed-mashiny@ru-legal-skills
```

**Codex CLI, через тот же маркетплейс:**
```
codex plugin marketplace add serjdrej/ru-legal-skills
codex plugin add gost-ed-mashiny@ru-legal-skills
```

Обе команды читают один и тот же `.claude-plugin/marketplace.json` в
`ru-legal-skills` — отдельного манифеста для Codex не нужно; источник этого
плагина там закреплён формой `"url"` (не специфичной для Claude Code формой
`"github"`), проверенной вживую на обоих рантаймах.

**Отдельно, без маркетплейса** — склонировать репозиторий в директорию
скиллов Claude Code (`~/.claude/skills/gost-ed-mashiny` — на других
CLI-рантаймах может отличаться, см. их документацию):
```
git clone https://github.com/serjdrej/gost-ed-mashiny.git ~/.claude/skills/gost-ed-mashiny
```

### Внешняя зависимость

Последний шаг (выпуск готового комплекта в DOCX) использует skill
`anthropic-skills:docx` — он не входит в этот репозиторий и не входит в
маркетплейс `ru-legal-skills`, устанавливается отдельно, из своего
источника. Без него все шаги до выпуска работают как обычно; сам комплект
можно собрать и сохранить как Markdown, просто без автоматической сборки в
DOCX.

## Как это устроено

Точка входа — [`SKILL.md`](SKILL.md): последовательность из шести шагов
(анкета исходных данных → форма подтверждения соответствия → РЭ → паспорт →
аудит → выпуск в DOCX), каждый шаг ссылается ровно на один файл из
`references/`.

```
SKILL.md
references/   — 6 модулей: анкета исходных данных, структура РЭ, структура паспорта,
                аудит по ТР ТС 010/2011, стиль и терминология, реестр норм
scripts/      — gost_lookup.py: статус ГОСТ по открытому каталогу Росстандарта
                и официальный маршрут к ТР ТС 010/2011
```

**Статус:** самостоятельный репозиторий, входит в маркетплейс
[`ru-legal-skills`](https://github.com/serjdrej/ru-legal-skills) вместе с
[`legal-ru`](https://github.com/serjdrej/legal-ru),
[`patent-ru`](https://github.com/serjdrej/patent-ru) и
[`arbitrazh-ru`](https://github.com/serjdrej/arbitrazh-ru). Также
импортирован (для чтения через `search_skills`, не для установки как
плагина — `.claude-plugin/` не переживает импорт с ведущей точкой в имени)
в `lazy-skill-library/library/skills/upstream/gost-ed-mashiny`.

## Тестирование

«Протокол пробела в базе» (`SKILL.md`) прогнан 2026-09-14 по методике
RED→GREEN→REFACTOR (та же, что у `legal-ru`): baseline-агент без скилла и
агент со скиллом отвечали на одинаковые три вопроса вне реестра. RED отвечал
по существу на все три, с честными оговорками, но не спрашивая пользователя.
GREEN верно классифицировал все три, реально выполнил `gost_lookup.py
trts-route` и живьём проверил найденный регламент (ТР ТС 004/2011) через
браузер, и для двух вопросов вне базы (предельный уровень шума по ГОСТ
12.1.003, требования CE-маркировки) отказался отвечать по существу и вернул
пользователю вопрос — вместо того чтобы выдать правдоподобный ответ.

GREEN-прогон также вскрыл реальный пробел в формулировке: вопрос про ГОСТ
12.1.003 одновременно относился и к случаю 1 (статус акта можно проверить
живьём), и к случаю 2 (само нормируемое числовое значение шума заперто
отдельным «Жёстким правилом» независимо от статуса акта) — протокол не
описывал этот составной случай явно. Исправлено в `SKILL.md`.

## Проверка кода

`python scripts/test_gost_lookup.py` — 25 тестов, stdlib `unittest`: часть
без сети (нормализация обозначения, выбор каталога, включая латинскую «P»),
часть с подменённым `urlopen` для веток отказа (страница недоступна, снимков
на странице несколько — выбирается самый новый, кодировка не распознана,
неверный CSV), и два прогона с реальной сетью, которые пропускаются, а не
падают, если сеть недоступна.
